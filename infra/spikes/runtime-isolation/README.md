# EL-TK-060 bounded isolation / quiescence experiment

Run from repository root in PowerShell: `./infra/spikes/runtime-isolation/Run.ps1`, then `./infra/spikes/runtime-isolation/Scratch.ps1`, then `./infra/spikes/runtime-isolation/Evaluate.ps1`.

Requires the existing healthy EL-TK-059 laboratory. No new image/dependency/provider, Docker socket mount, permanent executor or multimedia adapter is introduced. The host controller can pause **only** the PostgreSQL container with the exact EL-TK-059 Compose project label. It restores the service in `finally`. Synthetic fixture containers have their own `eventlens.spike=060` label and are removed by their recorded exact ID/name. Existing volumes remain intact.

## Experimental plan and dimensions

1. Untrusted parser fixtures: UID1000, no network, readonly root and input mount, no secrets, all capabilities dropped, no-new-privileges; CPU0.5, 128MiB RAM, PIDs32, private scratch16MiB. Thread-pressure case uses512MiB to measure PID/thread exhaustion independently of OOM. Maximum host wall observation8s, stop deadline4s. CPU throttle is measured from cgroup counters; OOM uses a bounded allocator; process/thread budgets reject allocations; scratch reaches ENOSPC. Header guards are synthetic pre-allocation pixel/stream checks, not codec validation.
2. Real PostgreSQL authority and durable attempt inventory precede real S3 requests. Supervisor polls authority every40ms. Separate fault cases revoke lease/token, stop short-lease heartbeat renewal, cancel, advance fence/generation/epoch, and pause the real PostgreSQL service. Invalid/unknown authority closes admission, kills the subprocess group and aborts its client. Descendant PID is recorded before loss and verified not running afterward. Stale renewal and promotion CAS must reject.
3. Independent fault-injection relay retains signed PUT/CompleteMultipart requests after client abort or adapter-process SIGKILL. This deliberately demonstrates that SQL fencing/client cancellation alone cannot stop a remote write. Inventory remains UNKNOWN and physical completion is refused until the relay observes real MinIO response drain and HEAD. Late objects are removed only afterward. Known multipart upload IDs are aborted and ListParts confirms absence.
4. Recovery uses an independent SQL connection and durable inventory after a real adapter-process crash with an in-flight PUT. Recovery waits for external drain before removing its scoped partial. Protected original/active fixture hashes remain unchanged. Two live parser containers use identical private scratch paths with independent contents. A crash/new attempt cannot expose old scratch; removed containers discard private tmpfs.

Evidence is separate `../evidence/spike060-*.json`. Each global check must pass; `Evaluate.ps1` returns FAIL if any required check is missing/failed. No Beta validation gate or EL-TK-061 execution is certified. The initial real run's DB-fault handshake failure is retained as `spike060-integration-attempt1.json`; the controller acknowledgment contained a UTF8 BOM, which was subsequently handled explicitly.

The relay is a bounded fault injector representing an external request surviving caller death, not a proposed production relay architecture. Candidate recommendation is for architect review; final tools/adapters/configuration remain downstream decisions supported by experiments.
