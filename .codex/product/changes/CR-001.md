# CR-001 — Despliegue monolítico EC2 para el MVP

## Date

2026-10-07

## Requester

Usuario / promotor de EventLens.

## Type

Technical change; sustitución parcial de restricción operativa previa.

## Original request

DEC-060 ACCEPTED: primer MVP como aplicación monolítica en una única AWS EC2 con frontend, API, PostgreSQL, Redis si necesario, procesamiento multimedia, almacenamiento local persistente, Nginx y Docker Compose. Código modular con abstracciones para futura migración de almacenamiento a S3, base de datos a RDS y medios a workers independientes.

## Reason / need

**CONFIRMED:** reducir complejidad operativa y costes durante validación inicial del flujo completo.

## Definition status

ACCEPTED histórico — parcialmente sustituido por CR-002/DEC-061..064. TC-001..004 RESOLVED/ACCEPTED; diseño concreto y validación pendientes en CR-002.

**Vigencia:** las siguientes secciones de impacto conservan la situación histórica de CR-001. CR-002 requirió PostgreSQL separado/administrado, media externa y workers async. Esa exigencia de separación física DB/app queda posteriormente SUPERSEDED sólo para Beta por DEC-106/EL-TD-008; la restricción de media Beta externa permanece. Conserva app inicial única, operación simple, modularidad y Nginx/Docker Compose donde correspondan.

### Tickets

Sin tickets existentes ni nuevos; no hay contratos implementados que migrar.

### Data

**CONFIRMED:** PostgreSQL y archivos persistentes operados en EC2 durante MVP. Originales y derivados siguen separados; estados/consumo/papelera no cambian. **RECOMMENDED:** referencias de almacenamiento independientes de rutas y persistencia durable fuera de la capa efímera de contenedores. **PENDING:** volúmenes concretos, layout, copias y sincronización de recuperación entre DB/archivos.

### APIs/contracts

**CONFIRMED:** abstracción de almacenamiento para S3 futura, compatibilidad de PostgreSQL con RDS y separación modular de medios para workers futuros. No cambian contratos funcionales. **PENDING:** interfaces técnicas concretas, entrega privada, jobs/reintentos, reanudación e idempotencia. Nginx no debe exponer directamente todo el árbol de archivos privados.

### Permissions

**CONFIRMED:** autorización por actor/evento/estado, IDs impredecibles, acceso temporal protegido, cuarentena no publicable, administración con justificación y auditoría siguen vigentes. Localidad física no concede acceso a otros eventos ni acceso indiscriminado de administrador. TLS/cifrado cuando aplique siguen requeridos.

### Integrations

**CONFIRMED:** EC2, PostgreSQL, Docker Compose y Nginx; Redis opcional. Almacenamiento/procesamiento locales durante MVP; S3/RDS/workers como evolución. **PENDING:** correo, herramientas multimedia, backup/monitoreo, tipo EC2, volúmenes y coste. No se asume Redis, EBS, S3 backups ni un producto de backup como decisión aceptada.

### Tests

**RECOMMENDED:** antes de beta, demostrar persistencia tras recreación de contenedores/reinicio; restauración coordinada de originales y DB; ausencia de exposición/escape de rutas entre eventos; aislamiento de cuarentena; cargas/reintentos concurrentes sin corrupción; saturación y espacio bajo sin pérdida de confirmados; límites operativos de transcodificación y ZIPs concurrentes; purga de temporales/backups y no resurrección; observación de host caído desde fuera de su único punto de fallo. Verificar objetivos de latencia, disponibilidad y retención; no hay implementación para ejecutar estos tests en esta fase documental.

### Roadmap

**RECOMMENDED:** concretar TC-001 a TC-004 con `architect` durante fundamentos, y revisar contratos con `requirements_reviewer`. La beta completa exige validación de capacidad/recuperación bajo EC2 única. No cambia prioridad ni calendario; no añade épicas de infraestructura. La futura migración tiene abstracciones confirmadas, fecha/umbral PENDING.

## Conflicts and retained objectives

- **CONFIRMED:** supersesión parcial de object storage/no disco local durante MVP; controles de privacidad y retención permanecen.
- **CONFIRMED:** 99,5% mensual sigue objetivo, sin SLA. **Riesgo:** host único concentra fallo/mantenimiento; su cumplimiento no está demostrado ni descartado automáticamente.
- **CONFIRMED:** backups automáticos diarios ≥7 días y recuperación verificable; PITR preferible si solución permite. **Riesgo:** copias únicamente en el mismo fallo no prueban recuperación ante pérdida de host/volumen.
- **CONFIRMED:** cuotas 1500 archivos/10 GB, fotos25 MB, videos500 MB/5min y exportaciones ~5 GB/48h se conservan. **Riesgo:** cuota por evento no cubre disco total, derivados, uploads parciales, ZIPs, backups, DB y logs; medios/exportaciones compiten por CPU/RAM/I/O con API/DB. PL-011/012 siguen bloqueantes funcionales de cuotas.
- **CONFIRMED:** aislamiento privado y originales intactos siguen requeridos; rutas locales y montajes compartidos requieren diseño seguro.
